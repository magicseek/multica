# Chat Contracts

> Backend contracts for chat sessions, messages, title provenance, and
> websocket-visible chat state.

## Chat Session Titles

Chat session titles are generated by multiple actors. `title_source` is the
contract that decides which actor may overwrite the current value:

- `legacy`: empty or pre-provenance title. The first user message may replace
  it.
- `first_message`: title derived from the first user message. It may be
  corrected only while the session has exactly one user message, which covers
  stale client seeds created before the authoritative send.
- `agent_summary`: title produced by a structured chat summary. It may replace
  generated titles but must not replace a user title.
- `user`: explicit rename through the chat session update API. No generated
  title path may overwrite it.

Project-associated chat sessions often start from route context before the
first message is durable. Do not treat a client-created title as final simply
because it is non-empty. The server must derive the first-message title after
`CreateChatMessage` succeeds, then broadcast `chat:session_updated`.

## First-Message Title Rules

- Derive the first-message title from normalized user content, capped to
  `chatSessionFirstMessageTitleMaxLen`.
- Insert the user message before setting the title so the query can verify the
  session has exactly one user message.
- Preserve user-renamed titles by filtering out `title_source = 'user'`.
- Do not keep retitling the session on later user messages.
- If old Project sessions used the Project title as a client seed, repair them
  only when `title_source = 'first_message'`, the stored title matches the
  project snapshot title, and a first user message exists.

## Realtime Visibility

Every title update that should be visible without a refresh must publish
`chat:session_updated` with `chat_session_id`, `title`, and `updated_at`.
Clients must patch:

- the unfiltered chat sessions query,
- every filtered chat sessions query, including Project-scoped lists,
- the single chat session detail query,
- then invalidate session lists/sidebar for authoritative reconciliation.

## Regression Checklist

- [ ] Handler tests cover empty/legacy first-message title creation.
- [ ] Handler tests cover stale first-message title correction on first send.
- [ ] Handler tests prove user-renamed titles are not overwritten.
- [ ] Realtime cache tests cover filtered sessions lists and single session
  details.
- [ ] Data repair migrations do not rewrite `title_source = 'user'`.
